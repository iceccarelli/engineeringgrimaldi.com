The cluster is software that observes, predicts, simulates, optimizes, coordinates, and eventually safely controls distributed energy infrastructure.

OBSERVE → PREDICT → SIMULATE → OPTIMIZE → RECOMMEND → AUTHORIZE → EXECUTE

The company should eventually connect DERs + BESS + PV + EVs + buildings + microgrids + energy communities + aggregators + grid operators. Do not position this as generic "AI for energy." The positioning must be specific, economically measurable, and technically credible.

## 4. Hard separation rules

Keep components isolated when coupling creates cybersecurity risk, OT risk, certification risk, deployment risk, vendor lock-in, unnecessary dependencies, excessive blast radius, or unclear ownership. Especially isolate AI planning from deterministic safety enforcement. The LLM/agent must NEVER directly control a physical system.

LLM/Agent → Planner → Candidate Actions → Simulator → Physics Constraints → Policy Engine → Risk Evaluation → Authorization → NeuralBridge → Actuator. Never bypass the safety boundary.
